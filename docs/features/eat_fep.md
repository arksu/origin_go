# Eat & FEP в Haven and Hearth

**TL;DR:** еда в H&H делает три вещи одновременно: даёт **энергию** (калорийный резерв), заполняет шкалу **голода** (аппетит) и начисляет **FEP** (Food Event Points) на скрытую шкалу. Когда FEP-шкала набирает количество, равное вашему **наивысшему атрибуту**, один из атрибутов повышается на +1 или +2 — какой именно, определяется пропорционально составу съеденного. Система спроектирована так, чтобы наказывать однообразную еду (сатиации), поощрять застолья (симбел) и возвращающихся игроков (голод 300%).

## Что происходит при еде

Игрок кликает ПКМ по еде → «Eat» — потребление почти мгновенное, серверное. Альтернатива — **режим пира**: сесть на стул, ПКМ по накрытому столу → Feast, кликать еду в инвентаре стола (бонусы применяются). Каждая съеденная еда даёт:

- **Energy** — всегда, независимо ни от чего (качество еды на энергию не влияет);
- **Hunger** (заполнение шкалы аппетита) — уменьшается сатиацией и модификатором стола;
- **FEP** — только если Energy ≥ 8000/10000 **или** вы едите за симбел-столом. Без стола на низком стиле еда даёт только энергию, FEP — ноль.

## FEP-цикл (ядро прокачки)

Каждый продукт несёт набор «событий» вида `(стат, +1 или +2, базовое значение FEP)` — например, Midnight Blue Cheese даёт событие STR+2 силой 50 FEP, свёкла — 0.5 PER + 0.2 CHA. Съедая еду, вы заполняете одну скрытую FEP-шкалу; каждое событие добавляет свои FEP с меткой стата.

1. Порог срабатывания = **ваш наивысший атрибут без модификаторов** (STR 57 → нужно 57 FEP). Отсюда совет качать статы равномерно — дорогой стат делает все остальные наборы дороже.
2. При заполнении выбирается один стат — **пропорционально доле его FEP в шкале** (пример с форума: 4.0 STR против 4.8 INT из 8.8 → шанс 45.5% / 54.5%).
3. Атрибут получает **+1 или +2** согласно метке события. Шкала сбрасывается, **излишек сгорает** (но успевает повлиять на выбор стата).
4. Повышение **перманентно** — в современной игре (W13–W16) атрибуты не декеют. Также их поднимают Credos. Экипировка не может поднять атрибут выше базового значения.

## Variety bonus (поощрение разнообразия)

Формула Loftar'а (пост t=9383): каждый **новый тип еды** с прошлого повышения атрибута снижает требование на **≈ 0.632 · √(наивысший стат)** с округлением вверх до 0.1 (внутреннее представление FEP — десятки видимых единиц, отсюда `2√(max·10)/10`). Множитель зависит от уровня голода (~1.10 на 300%, 0.89 на 200%, 0.63 на 150%, ~0.60 на 100%). Считается *тип* еды, а не её FEP — черника и лисичка дают один INT, но обе считаются. После каждого пойнта набор «уникальных» продуктов сбрасывается.

## Полная формула получения

```
FEPGained   = baseFEP × QM × HungerEff × TableFEP × Account × Bonfire × Π(сатиации)
HungerGained= FoodHungerValue × TableHungerMod × Π(сатиации)
EnergyGained= FoodEnergyValue  (не масштабируется ничем, кроме редких исключений)
```

| Модификатор | Значение |
|---|---|
| Качество QM | √(Q/10): Q40=×2, Q90=×3, Q160=×4 — растит только FEP, не голод/энергию |
| Эффективность голода | 300%→200%→150%→100%→90%→75%→50% по уровням Ravenous…Overstuffed |
| Сатиации | 18 категорий (мясо, хлеб, ягоды…), каждая от 100% до 0%, **перемножаются** — одна на 15% убивает всю пользу еды |
| Симбел-стол | до ~65% FEP-бонуса (золотая/серебряная посуда) + снижение заполнения голода |
| Аккаунт | verified +10%, подписка +30% |
| Костёр | Σ модификаторов голода столов × средняя харизма пирующих |

Голод — единственная шкала, которая **тикает сама в реальное время** (онлайн или офлайн): ~2 ч на 1% при 300% и ~7 секунд при 50% (W14: скорость ∝ кубическому корню уровня). Поэтому «постоять голодным» перед застольем — базовая стратегия, а спам еды — самострел.

**Сатиации** стартуют скрытыми на 100% и падают с шансом, указанным на еде (зависит от качества); с патча Hungry Hat (2021) растут/восстанавливаются в 3 раза медленнее. Напитки дают счётчики («Drink and be merry», 0.05 л = 1 счётчик, живёт ~8 ч): молоко гасит сатиацию хлеба на 25%, мёд — овощей, пиво — колбасы, бренди — десертов (35%) и т.д. Правило сброса из гайда W11: когда 4 сатиации ≤49%, минимальная сбрасывается в 100% — под это держат «буферные» категории.

**Симбел** деградирует: каждый предмет стола копит износ с шансом при каждом съеденном юните, при максимуме уничтожается, бонусы падают (золото изнашивается медленнее всех). Дубликаты одного типа не стакаются. FEP-бонус стола не делится с пирующими — делится только костёрный (голодный).

## Атрибуты и их эффекты

Девять статов (в origin_go enum уже совпадает): STR (урон = √STR + бонус инструмента, майнинг, переноска), AGI (кулдауны в бою), INT (внимание для кюриозити, авторитет с CHA), CON (MHP = 100·√(CON/10), стоимость плавания), PER (форажинг, софткап качества теста = PER·Cooking), CHA (размер пати, бонусы пиров), DEX (качество керамики/шитья, взлом), WIL (слоты рыбалки = 1+⌊WIL×Survival/20⌋, travel weariness), PSY (ювелирка, шелк, пигмент = Psyche×Cooking²).

**Клиент** формулы не содержит: тултип еды приходит с сервера (поля `end`/`glut`/`cons`/`evs`/`efs`/`sev` в FoodInfo hafen-client), шкалы рисуются из серверных сообщений.

## Что это значит для origin_go (проверено по коду)

Уже есть: `EntityStats{Stamina, Energy}` (Energy ≈ фуд-метр, 1000/1100), все 9 имён атрибутов в `internal/characterattrs/attributes.go`, гейтинг регена HP от Energy, урон от голода при Energy<500, качество предметов и `weighted_avg_floor`, конвейер действий (`plow_tile` как образец) и S2C_PlayerStats с полем energy.

Чего не хватает для порта механики: действие eat (нет ни actiondef, ни C2S_UseItem), питательная ценность на `ItemDef` (сейчас только теги), путь инкремента атрибутов в рантайме (CharacterProfile статичен), трекинг сатиаций/уникальных типов еды и тик голода в реальном времени (инфраструктура behavior-tick уже есть и переиспользуема).
