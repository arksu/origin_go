# Herbalist Table в Haven & Hearth — анализ

## Суть механики (самое важное)
Стол травника — это **станция-контейнер без топлива и без «кнопки запуска»**: кладёшь предметы-предшественники в контейнер стола и просто ждёшь. **Каждый предмет в каждом слоте ведёт свой таймер независимо и параллельно**, обработка идёт серверно, а результат заменяет вход в том же слоте. Процессы **сцепляются автоматически**: чайный лист → зелёный чай (2 игровых часа) → если не забрал → чёрный чай (48 ч); семя пшеницы, оставленное на столе, само прорастает в солод; горшок с рассадой «выстреливает» сам. Это ключевое архитектурное отличие от печей/горнов (там топливо и активное управление) и то, что в первую очередь надо воспроизвести у нас.

## Параметры станции
- Постройка: навык **Plant Lore**; 4 блока дерева + 4 доски + 8 лучшего растительного волокна; ремонт — волокно (в legacy — 4 доски).
- **Контейнер 4×4 слота**, след 1.1×0.7 тайла, **можно поднимать/переносить**, в помещении не обязателен, есть смещение по пикселям (соседние столы занимают 7/11 тайла — «фабрики шёлка»).
- **Q стола = среднее материалов**: (qВолокно + qДоски + qБлоки)/3 — у нас это ложится прямо на существующее качество-взвешенное построение.

## Правила качества (центральное дизайн-решение)
- **Общее правило: Q результата = среднее(Q входа, Q стола)**, дробное — вниз. То есть стол — это **качественный мост**: низкокачественный вход тянется вверх хорошим столом, а высокий вход — размывается плохим столом.
- **Единственное исключение — WWW → семена: Q семян от стола не зависит вообще** (стол любого Q годится;_seed faucet не капится станцией).
- **Q стола не влияет на скорость** — ровно зеркально к Drying Frame, у которого Q влияет только на скорость (100×(q/10)^⅓) и никогда на результат. Две станции, две оси: «скорость» против «качество».
- Чёрный чай — особый случай: результат смещается **к качеству стола** (не броди зелёный чай на столе хуже листа).
- Пророщенное дерево (через Treeplanter's Pot): вклад всех факторов — wiki-формула (qПочва·2 + qВода·2 + qГоршок·3 + qСтол·3 + qСемя·15)/25 ± (−5,+5) софткапом по Farming; шанс прорастания улучшают Plant Lore/Woodsmanship < Forestry < Druidic Rite. Важно: **семя вносит 15/25 веса** — дерево в основном «наследует» семя.

## Legacy-версия и отличия
- Размер 1×2, ремонт 4 доски, материалы с обычным (не «лучшим») волокном.
- **Формула Q стола другая: (2·qВолокно + qДоски + qБлоки)/4** — вес волокна менялся между версиями; при переносе берём одну формулу и фиксируем.
- Существовал табак (→ заменён пайпвидом), выдерживание 6 дней/40 ч (сейчас 5 д/36.5 ч), изюм был 2 дня (сейчас 2:46 — сильно ускорили), проращивание зерна в pre-2.0 было «not yet implemented».
- Была известная игрокам уловка определения Q стола: положить предметы чётного и нечётного Q и вычислить Q стола из результатов (Max(2·Qвых−Qвх)). Полезный сигнал: игроки **не видят** Q станции напрямую в UI — это решение дизайна, которое мы можем сделать лучше (у нас inspect уже есть).

## Что берём в origin_go (срез для фичи, без кода)
1. **Стол = объект-станция с прикреплённым контейнером** (инвентарная система и контейнеры у нас есть, постройка — через существующий build-site поток).
2. **Процессы — как behavior-состояние станции**: на каждый занятый процессом слот свой таймер в тиках, диспетчеризация через `ScheduleBehaviorTick`, арифметический догоны после рестора — точный прецедент уже есть: `BurnerBehavior` (`NextFuelBurnAtTick`, catch-up, IsDirty). Слоты обрабатываются параллельно, автосцепка (чай) = по завершении перезапланировать следующий этап, если выход сам обрабатываемый.
3. **Процессы — data-driven** (описание в конфиге объекта: вход → выход → тики → правило Q), не хардкод.
4. **Q-правило avg(вход, стол)** совпадает с нашим `QualityWeighted` крафтом; **переопределение для WWW** — seed-Q никогда не зависит от стола.
5. **Первый срез под farming**: сушка WWW → семена (главная роль стола) + прорастание зерна (4/тайл), остальное (чай, шёлк, губки) добавляем вместе с соответствующими предметами. Проростки деревьев — когда появятся деревья.
6. Открытые решения до пропозала: давать ли игроку видеть Q стола в inspect (H&H не даёт), обрывать ли автосцепку ручным флагом «забрать после этапа», сколько слотов (4×4 = 16 дорого по UX — можно меньше).
