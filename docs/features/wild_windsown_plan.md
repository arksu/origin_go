# WWW: генерация, учёт в споте и behavior

## Текущий этап

Mapgen создаёт зрелые Wild Windsown Weed обычными объектами мира. Behavior
`wild_weed` обеспечивает сбор и отрастание того же растения. Уничтожение удаляет
объект и его запись в споте одной транзакцией. SpotManager вероятностно пополняет
дефицит стеблями; строгих сроков восстановления и отдельной очереди замен нет.
Старые миры без коллекции `www.objects` автоматически не заполняются.

## Первоначальное размещение

После сохранения террайна, деревьев и валунов финальная транзакция mapgen создаёт
споты, читает их настоящие ID, размещает WWW и записывает их актуальный список.
В той же транзакции обновляются `entity_count` затронутых чанков и итоговый
`LAST_USED_ID`. Ранний checkpoint деревьев сохраняется: их записи уже существуют
вне финальной транзакции. Ошибка этапа откатывает споты, WWW и финальный checkpoint.

Цель на спот: `floor(0.0004 * pi * (radius / CoordPerTile)^2)`, то есть 5 растений
для радиуса 64 тайла. Недостаток подходящих позиций уменьшает фактическое число.

- Проверяется окончательный террайн **каждой** позиции: только тайлы 20, 25, 35, 50.
  Мелкая и глубокая вода запрещены, даже когда центр спота находится на суше.
- Позиция — центр тайла внутри круга и границ мира.
- До координат любого другого объекта того же региона и слоя требуется
  расстояние не меньше 20 мировых единиц: `dx*dx + dy*dy >= 400`.
  Ровно 20 допустимо. Коллайдеры, размеры и типы объектов не проверяются.
- Позиции читаются существующим `GetObjectsByChunk` для области спота с полем
  20 мировых единиц, включая соседние чанки. Принятый WWW сразу занимает позицию.
- Отдельный RNG использует seed карты и район, а не SpotID. Генерация деревьев,
  валунов и геометрии спотов не меняется. При перекрытии владелец точки имеет
  максимальное вычисленное Q; равенство разрешается по `(districtY, districtX)`.

Качество: `10 + floor((peakQuality - 10) * (1 - distance / radius))`.
Сохраняются обычные EntityID, TypeID, позиция, Q и behavior state стадии 3.
Начальное HP берётся из определения при загрузке, как у деревьев и валунов.

## Состояние спота и уничтожение

```json
{"www":{"objects":{"123":{"x":456,"y":789}}}}
```

Это актуальная коллекция принадлежащих споту WWW. Ключ — точная десятичная запись
EntityID; координаты — мировые. Пустая коллекция — `{}`. Тип, Q, HP, стадия и срок
роста сохраняются в объекте, отдельно в список не копируются.

Сбор, рост, загрузка и выгрузка коллекцию не меняют. Выгруженный WWW остаётся
в списке. Уничтожение любой стадии и административный `/destroy` атомарно удаляют
обычный объект и ровно его ключ в актуальном JSON спота. Остальные поля сохраняются.
Revision растёт только при фактическом удалении ключа; runtime обновляется через
`GREATEST`. Повтор после неоднозначного commit возвращает текущий снимок без
повторного увеличения revision/runtime.

Используются существующие операции и workers уничтожения. Снимок удерживается
в операции до применения owning shard; старое подтверждение не заменяет более
новую revision. Список WWW в runtime не записывается самостоятельным `SaveState`.
Новых фоновых jobs и очередей нет. SpotManager по-прежнему хранит один экземпляр
спота независимо от количества пересекающих его чанков.

Для `/destroy` первая запись остаётся синхронной. До неё резервируются существующий
слот уничтожения и pin чанка. При ошибке БД или применения подтверждения растение
изолируется, а операция удерживает исходные SpotID, EntityID и runtime до повтора
через существующие workers. Чанк не выгружается и не сохраняет этот источник до
подтверждения; потерянный ответ commit не может воскресить WWW без записи в споте.
Подтверждённый commit при ошибке применения повторно в БД не отправляется.

## Вероятностное пополнение стеблями

`SpotManager.Update` работает под shard lock после обновления чанков. Список
WWW-спотов и индекс пересечений неизменяемы; за вызов проверяются до 32 спотов
по кругу. Для участия нужен загруженный активный чанк с настоящим активным
AOI-интересом и законченным восстановлением raw-объектов. Одних pins недостаточно.

Каждые 900 runtime-секунд на весь спот приходится одна попытка с вероятностью
`1/120`: в среднем один стебель за 30 runtime-часов независимо от дефицита.
Полные пропущенные периоды учитываются при следующем активном посещении;
геометрические интервалы между успехами позволяют пропускать неудачные попытки.
Остановка сервера не продвигает runtime. Все записи `www.objects`, включая
стебли и выгруженные растения, занимают норму. Дефицит после mapgen тоже пополняется.

Необязательный `www.last_check_runtime_seconds` хранится в существующем JSONB.
Первое фактическое уничтожение устанавливает его в своей транзакции, последующие
удаления не сбрасывают. Недозаполненный спот без маркера начинает отсчёт при первом
активном посещении. Обработанные полные периоды продвигают маркер, в том числе
при неудачных розыгрышах или отсутствии свободных позиций. Полный спот удаляет
маркер и больше не выполняет периодических записей. Отрицательный интервал — ноль.

Размещение использует те же общие правила количества, террайна, владения, Q и
зазора, что mapgen. Кандидаты — случайные центры тайлов активной части спота.
Соседние чанки проверяются через локальный spatial и raw-кэш; недоступная область
пропускается без загрузки. На одно появление допускается 64 кандидата; общий
бюджет вызова — 64 кандидата и четыре подготовленных объекта. Необработанные
успехи остаются в принятой pending-операции, выбранные позиции служат резервами.
До розыгрыша готовые исходные чанки закрепляются pins. Их последующие raw-вставки
от других подтверждённых операций учитываются при проверке зазора и не расходуют
попытки из-за временного backlog. Это сохраняет выпавшее количество при drain,
который не выполняет активацию чанков. Занятый I/O gate откладывает сам розыгрыш.

В одной транзакции создаются обычные объекты, точечно добавляются ключи в текущий
список, изменяется маркер, увеличиваются только `entity_count` затронутых чанков
и сохраняется checkpoint EntityID. Террайн не перезаписывается. При ошибке
сохраняются интервал, результат, ID, позиции и сроки роста. Повтор определяется
по подготовленным ID или сохранённому маркеру; отдельного durable-токена нет.
Незавершённая операция использует существующие workers, backoff и shutdown drain.

После commit owning shard применяет снимок по revision и публикует объекты через
`ReplaceCommittedSource`; до завершения удерживаются pins. Известный commit
повторно в БД не отправляется. Обычная активация добавляет растения в spatial,
и обычная система видимости сообщает о них также неподвижным игрокам.

Новый WWW имеет полное HP из def, Q новой позиции, стадию 0 и срок
`next_growth_runtime_seconds = runtime подготовки этого стебля + 28800`.
Пропущенные проверки не добавляют растению исторический возраст. Восстановление
behavior делает стебель проходимым и подключает существующий планировщик роста.
Первоначальная генерация mapgen продолжает создавать зрелую стадию 3.

## Behavior и клиент

Один объект и один предмет `wild_windsown_weed`: object def 41, item def 4006.
Растение статическое, HP 100, collider 4x4; предмет занимает одну ячейку.
State: `spot_id`, `stage`, `next_growth_runtime_seconds`.

Действие `wild_weed/pick` доступно только зрелой стадии, длится стандартные
10 ticks и стоит 10 stamina. Завершение повторно проверяет текущий цикл, цель,
игрока и возможность оплаты. Сначала выдаётся один WWW исходного Q; только
успешная выдача списывает stamina и переводит растение в стебель. Общий cyclic
runtime проверяет связь с целью. Неудачная выдача и отмена эффектов не имеют.

| Стадия | Срок после сбора |
| --- | --- |
| 0: стебель | Сразу |
| 1: молодое растение | 8 runtime-часов |
| 2: закрытые метёлки | 16 runtime-часов |
| 3: зрелое растение | 24 runtime-часа |

Используется существующий runtime-планировщик. Выгрузка не останавливает рост;
остановка сервера останавливает. При восстановлении просроченные переходы
догоняются ограниченно — их максимум три. EntityID, TypeID, Q и оставшееся HP
не меняются. Зазор 20 проверяется при mapgen и пополнении; рост проверок размещения не делает.

Стадии 0–2 проходимы через `Collider.Layer = Collider.Mask = 0`, но остаются
доступны обычному урону. Зрелость возвращает маски из def. Административно созданный
WWW имеет `spot_id = 0` и не меняет коллекции спотов.

Четыре утверждённых изображения 32x40 используют anchor `(16,36)`.
`tools/export_wild_windsown_sprites.py` также экспортирует иконку 30x30 из зрелого
изображения. Сбор использует опубликованный binding `wild_weed_pick` и `pick_up`.
В `seedOutcomes` перечислены `seed_wheat`, `seed_carrot`, `seed_beet`, `seed_potato`.
Тип семени в WWW не хранится; сушка в этот этап не входит.
Семена свёклы и картофеля используют утверждённые иконки beet B и potato A.
`python3 tools/export_seed_icons.py --check` проверяет их источники и экспорт
в прозрачные PNG 30×30 без сглаживания пикселей.

## Проверки

Регрессии покрывают воду и whitelist, границу расстояния 19/20, соседние чанки,
владение и Q, воспроизводимость, актуальный список, checkpoint и rollback mapgen.
PostgreSQL-тесты проверяют конкурентные удаления, большие ID, неизвестные поля JSON,
повтор commit и атомарный откат. Game-тесты проверяют capture до quarantine,
применение только owning shard, повтор операции, очистку reused slots и обычный
урон всех стадий. Behavior-тесты покрывают отказ выдачи, stamina, отменённые циклы,
двойной сбор, runtime-переходы и сохранение HP/Q/ID.

Обязательные команды: `make test`; в `web_new` — `npm run type-check`,
`npm run lint`, `npm run test:action-animations`, `npm run test:inventory-item`,
`npm run test:asset-pipeline`, `npm run validate-objects`; для ассетов —
`python3 tools/export_wild_windsown_sprites.py --check` и проверки из `tools/README.md`.
