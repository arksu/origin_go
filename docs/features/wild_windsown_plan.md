# Wild Windsown Weed: сбор, сушка и семена

## Зафиксированная механика

Первый этап — дикий WWW → сбор рукой → автоматическая сушка → семена. Посадка и рост культур остаются следующим этапом.

| Параметр | Значение |
|---|---|
| Появление | Только новые карты; луг, оба типа леса и болото |
| Патчи | Шаг 64 тайла, один тип семян на патч |
| Качество WWW | Q10–50, выше ближе к центру патча |
| После сбора | Срезанный стебель; отрастание через 24 часа работы сервера |
| Drying Frame | Контейнер 2×2, постройка за одну ветку |
| Сушка | 300 секунд — фиксированное тестовое значение, независимо от Q рамки |
| Результат | Один WWW заменяется одним предметом семян в том же слоте |
| Семена | Пшеница, морковь, свёкла, картофель; без стопок |
| Качество результата | Равно качеству WWW |
| Доступность | Без навыковых требований, скрытой видимости и мирового catch-up |

## Реализация сервера

- **Генерация:** добавить независимый поток координатных хешей от seed карты. Центры патчей смещаются до ±8 тайлов, радиус — 16 тайлов, до восьми растений на патч. Тип семян выбирается равновероятно; качество плавно падает от пика Q20–50 к Q10. Размещение не меняет существующий RNG деревьев и валунов.
- **Идентичность семян:** четыре определения объектов WWW и четыре определения собранного предмета с общими названием и графикой. Их `TypeID` сохраняет принадлежность к культуре через переносы, торговлю, выбрасывание и загрузку. Новые поля protobuf и SQL не нужны.
- **Сбор:** новый behavior `wild_weed`, действие `Pick`, существующая анимация и длительность сбора. На завершении повторно проверить цель, связь с игроком, состояние персонажа и место в инвентаре/руке. После успешной выдачи одного WWW сохранить срок отрастания, убрать collider и показать срезанный стебель.
- **Отрастание:** сохранить EntityID, тип и качество растения. Перед восстановлением collider проверить подходящий террайн, завершённую активацию чанка и отсутствие препятствий ограниченным пространственным запросом. При препятствии повторить через 60 секунд; при восстановлении просроченного растения выполнить эту проверку через планировщик.
- **Сушилка:** behavior `container` + `drying`; стандартная постройка за одну ветку, длительностью 20 ticks и стоимостью 8 stamina. Collider 24×8 координат мира. Каждый WWW обрабатывается независимо; рамка принимает только входы и результаты объявленных сушильных рецептов.
- **Скорость:** фиксированные 300 секунд из рецепта. Q рамки не влияет на длительность или результат. По завершении заменить WWW семенами с новым ItemID, количеством 1 и исходным Q; обновить версию инвентаря и всех открывших контейнер игроков.
- **Состояние:** WWW хранит срок отрастания; сушилка — до четырёх записей `{inputItemID, inputTypeID, completionRuntimeSeconds}`. Перемещение внутри сушилки сохраняет таймер; извлечение отменяет его, повторное помещение запускает заново.
- **Внутренние интерфейсы:** добавить `ScheduledRuntimeBehavior` и индексированный runtime-планировщик по generational handle и behavior. Использовать существующий `BehaviorTickSystem`, priority 313, общий бюджет 200 переходов: сначала прежние tick-задачи, затем runtime-задачи.
- **Изменения инвентаря:** синхронный callback после каждой успешной операции обновляет таймеры до следующей команды. Это покрывает извлечение и возврат в одном tick. Все изменения выполняются под блокировкой owning shard; периодических сканирований станций нет.

Сроки используют `RuntimeSecondsTotal`: учитывают время выгруженных чанков, сохраняются между запусками и приостанавливаются на время остановки сервера.

## Проверки и критерии готовности

- Детерминированность патчей на границах чанков и при разных количествах workers; корректные типы террайна, диапазон Q и сохранение размещения деревьев/валунов.
- Одновременный сбор двумя игроками, полный инвентарь, отмена действия и устаревшие handles; отсутствие повторной выдачи.
- Независимая сушка четырёх WWW, правильный тип и Q семян, новые ItemID, уведомления всех зрителей; извлечение/возврат в одном tick.
- Unload/reload, restart, offline pause, расхождение runtime и ticks, отмена расписания при despawn/transform.
- Отрастание при постройке или игроке на стебле, изменении террайна и ограничении пространственного запроса; постоянное количество сущностей.
- Выполнить `make test`; клиентские `type-check`, `lint` с проверкой diff, `test:asset-pipeline`, `validate-objects`; визуально проверить спрайты в мире, контейнере и руке. Завершить `git diff --check` и отчётом о проверках и commit status.

Drying Frame реализуется отдельным предварительным этапом, описанным в [drying_frame.md](drying_frame.md). Пока игровые процессы сушки не объявлены, рамка строится и открывается, но не принимает предметы. Добавление WWW, семян и их рецептов остаётся следующим этапом.
